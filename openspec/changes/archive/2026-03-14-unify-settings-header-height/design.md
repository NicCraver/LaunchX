## Context

LaunchX 的高级扩展设置界面包括多个设置页面（终端设置、剪贴板设置、AI 翻译设置等），每个页面都有一个顶部区域显示图标和标题。当前这些顶部区域的高度不统一，可能的原因包括：
- 图标尺寸不一致
- 标题字体大小不一致
- 内边距（padding/spacing）设置不同
- 布局约束或对齐方式差异

**当前状态：**
- 各设置页面独立实现顶部布局
- 没有统一的顶部组件或样式规范
- 视觉上存在明显的高度差异

**约束条件：**
- 必须保持现有设置页面的功能不变
- 需要兼容 SwiftUI 的布局系统
- 不能影响设置内容区域的显示

## Goals / Non-Goals

**Goals:**
- 统一所有高级扩展设置页面的顶部高度
- 标准化图标尺寸、字体大小和内边距
- 提供可复用的顶部布局组件或样式指南
- 确保视觉一致性和专业性

**Non-Goals:**
- 不重新设计设置页面的整体布局
- 不修改设置内容区域的样式
- 不改变设置页面的功能逻辑

## Decisions

### 1. 统一方式：创建共享的顶部样式规范

**决策：** 定义统一的顶部样式常量（图标尺寸、字体大小、间距），并在所有设置页面中应用这些常量。

**理由：**
- 简单直接，不需要重构现有代码结构
- 易于维护，修改样式只需更新常量定义
- 保持各页面的独立性，降低耦合

**备选方案：**
- 方案 A：创建共享的 SettingsHeaderView 组件 → 拒绝，因为各页面的顶部内容可能有细微差异，强制使用统一组件会降低灵活性
- 方案 B：使用 SwiftUI ViewModifier → 保留为后续优化方案，当前先用常量方式快速修复

### 2. 样式基准：以现有最佳实践为标准

**决策：** 选择一个视觉效果最好的设置页面作为基准，提取其顶部样式参数，并应用到其他页面。

**理由：**
- 避免从零设计，利用现有的良好实践
- 减少视觉变化，降低用户适应成本
- 可以快速验证效果

### 3. 实施范围：逐页面检查和修复

**决策：** 遍历所有高级扩展设置页面，逐一检查和调整顶部样式参数。

**理由：**
- 确保不遗漏任何页面
- 可以发现和修复其他潜在的样式问题
- 便于测试和验证

## Risks / Trade-offs

**[风险] 修改后可能影响某些页面的布局**
→ 缓解措施：在修改前截图记录当前状态，修改后逐页面对比验证；使用 git 分支便于回滚

**[风险] 不同页面的内容复杂度不同，统一高度可能导致某些页面显得空旷或拥挤**
→ 缓解措施：统一的是顶部区域的最小高度和样式参数，内容区域保持灵活；如果发现问题，可以微调间距

**[权衡] 使用常量而非组件化，未来维护时需要手动同步多处代码**
→ 可接受：当前优先快速修复视觉问题，后续可以重构为组件化方案

## Migration Plan

**部署步骤：**
1. 确定样式基准（选择最佳的设置页面）
2. 提取并定义统一的样式常量
3. 逐页面应用样式常量
4. 测试验证所有页面的顶部高度一致性
5. 合并代码并发布更新

**回滚策略：**
- 通过 git revert 恢复到修改前的版本
- 纯 UI 样式改动，不涉及数据层，回滚无数据风险

## Open Questions

- 是否需要为不同类型的设置页面（如带图片的页面 vs 纯文本页面）设置不同的顶部高度标准？
  → 初步判断：不需要，统一标准更简洁，除非测试中发现明显问题
- 是否需要同时统一设置页面的其他样式元素（如按钮样式、分隔线等）？
  → 待确认：当前聚焦顶部高度，其他样式问题可以作为后续优化
