## Context

当前高级拓展模块中的各个设置详细页面（TerminalSettingsView, ClipboardSettingsView, AITranslateSettingsView 等）在左上角的 icon 尺寸和标题文字大小上存在不一致的情况。这些页面都是独立的 SwiftUI 视图，各自定义了头部布局，导致视觉风格不统一。

此外，终端和剪贴板的 icon 图标设计需要优化，以提升整体 UI 美观度。

## Goals / Non-Goals

**Goals:**
- 统一所有高级拓展设置页面的头部样式（icon 尺寸和标题文字大小）
- 以 TerminalSettingsView 的当前样式为标准
- 重新设计终端和剪贴板的 icon 图标
- 确保修改后的样式在所有设置页面中保持一致

**Non-Goals:**
- 不修改设置页面的其他部分（除头部外）
- 不改变设置页面的功能逻辑
- 不重新设计其他模块的 icon（仅终端和剪贴板）

## Decisions

### 1. 以 TerminalSettingsView 为标准样式

**决策：** 将 TerminalSettingsView 的头部 icon 尺寸和标题文字大小作为统一标准。

**理由：**
- 需要选择一个现有的样式作为基准，避免重新设计
- TerminalSettingsView 是用户提到的参考标准
- 统一标准可以确保后续新增的设置页面也能遵循相同规范

**替代方案：** 创建全新的设计规范 → 被拒绝，因为增加了不必要的设计工作，且用户已明确指定参考标准

### 2. 直接修改各个设置视图文件

**决策：** 直接在各个设置视图文件中修改头部的 icon 和标题样式代码。

**理由：**
- 当前各个设置页面是独立的视图文件，没有共享的头部组件
- 直接修改是最简单直接的方式
- 修改范围明确，影响可控

**替代方案：** 创建共享的头部组件 → 暂不采用，因为这属于更大范围的重构，超出当前需求范围

### 3. Icon 设计方式

**决策：** 使用 SF Symbols 或自定义 SVG/PNG 资源来重新设计终端和剪贴板的 icon。

**理由：**
- SF Symbols 提供了丰富的系统图标，风格统一
- 如果 SF Symbols 无法满足需求，可以使用自定义图标资源
- macOS 应用中这两种方式都很常见

## Risks / Trade-offs

**[风险] 样式标准可能不适合所有页面** → 在实施前先检查 TerminalSettingsView 的样式，确认其适用性

**[风险] Icon 重新设计可能需要多次迭代** → 先提供初版设计，根据用户反馈调整

**[权衡] 直接修改 vs 创建共享组件** → 选择直接修改以快速实现，但未来如果需要更多统一性，可能需要重构为共享组件
